# 07 · 项目目录地图:这片代码森林长什么样

> 目标:拿到仓库里任何一个文件,都能大致说出它属于哪一层、负责什么。
> 方法:先记"总图",再记几个关键目录,别背文件。

## 总览:顶层都有什么

```
AstrBot-master/
├── main.py                 ★ 后端总入口(开发模式从这里启动)
├── pyproject.toml          项目"身份证":版本/依赖/命令行入口
├── requirements.txt        依赖清单(uv 其实读 pyproject,这里给 venv 用)
├── AGENTS.md               给 AI/贡献者看的开发约定
├── README*.md              多语言介绍
├── astrbot/                ★ 核心框架代码(Python 包,重点!)
├── dashboard/              网页控制台前端(Vue 3 项目)
├── docs/                   文档(mkdocs 结构,zh/en)
├── changelogs/             版本更新日志
├── scripts/                发布/构建等辅助脚本
├── tests/                  测试代码
├── Dockerfile / compose.yml   容器化部署
└── data/                   (启动后自动生成)配置/插件/数据都在这里
```

**看代码时,95% 的时间泡在 `astrbot/` 里。**

## `astrbot/`:整个框架的地图

```
astrbot/
├── core/                   ★★★ 框架内核(所有重要逻辑)
├── api/                    ★★  给插件作者用的"公开接口"层(大多只是转出口)
├── cli/                    ★    命令行工具实现(init/run/conf/plug/password)
├── builtin_stars/            自带的"官方插件"(也算插件,展示插件怎么写)
├── dashboard/                网页控制台后端服务(提供 API/静态文件)
├── __init__.py               (定义版本号等)
```

> **`core` vs `api` 的分工**:
> - `core/` 是"发动机内部",实现细节,普通插件作者通常不直接碰;
> - `api/` 是"对外操作面板",插件里 `from astrbot.api.all import *` 导入的公开能力大多从这里再导出。
> 想改框架看 `core`;想写插件看 `api` + 官方文档。

## `astrbot/core/`:内核各模块

```
core/
├── core_lifecycle.py         ★ 生命周期编排中心:启动/停止所有组件
├── initial_loader.py         ★ 最外层启动器(被 main.py / CLI 调用)
├── event_bus.py              ★ 事件总线:消息事件从这里分发给流水线
├── astr_main_agent.py         构建"主 Agent"(本地 Agent)
├── astr_agent_run_util.py      Agent 运行器(ToolLoopAgentRunner)
├── conversation_mgr.py         多轮会话/历史管理
├── persona_mgr.py              人格(人设)管理
├── astrbot_config_mgr.py       多配置实例管理
│
├── platform/                 ★★ 平台层:QQ/Telegram/… 每个平台一个适配器
│   ├── platform.py             适配器抽象基类 Platform
│   ├── manager.py              PlatformManager:按配置启动各适配器
│   ├── register.py             @register_platform_adapter 注册表
│   ├── astr_message_event.py   ★ AstrMessageEvent:统一消息事件(贯穿全框架)
│   ├── astrbot_message.py      统一消息体(文本/图片等)
│   ├── message_type.py         消息类型枚举(私聊/群聊…)
│   └── sources/                具体平台:qqofficial/aiocqhttp/telegram/…
│
├── message/                  消息组件定义
│   ├── components.py            Plain(纯文本)/Image/At/Reply… 组件
│   └── message_event_result.py MessageChain/MessageEventResult(回复结果)
│
├── pipeline/                 ★★ 消息流水线(核心处理链路)
│   ├── scheduler.py              PipelineScheduler:按阶段跑消息
│   ├── stage.py                  Stage 基类 + register_stage
│   ├── stage_order.py            各阶段执行顺序
│   ├── waking_check/             唤醒判断 + 匹配插件 handler
│   ├── process_stage/            ★ 分发:给插件?还是给 LLM?
│   └── respond/                  发送回复
│
├── provider/                 ★★ 模型提供商层
│   ├── provider.py              抽象基类(chat/stt/tts/embedding)
│   ├── manager.py               ProviderManager:加载/选择当前模型
│   ├── register.py              @register_provider_adapter
│   ├── entities.py              数据结构(ProviderMeta 等)
│   └── sources/                 OpenAI/Anthropic/DeepSeek/Ollama… 实现
│
├── star/                     ★★ 插件(Star)体系
│   ├── base.py                   Star 基类(插件都继承它)
│   ├── star_manager.py           PluginManager:扫描/加载/管理插件
│   ├── star_handler.py           EventType 事件类型 + handler 注册表
│   ├── register/                 各种 @register_* / @filter.* 装饰器
│   ├── filter/                   过滤器(按指令/正则/权限…匹配)
│   └── context.py                Context:塞给插件的"工具包"
│
├── agent/                    Agent 抽象层与工具循环
│   ├── agent.py                  Agent 基类
│   ├── context/                  上下文(记忆)压缩/管理
│   └── runners/                  本地 runner + 三方 runner(coze/dify…)
│
├── cron/                     定时任务(CronJobManager)
├── db/                       数据库(SQLite + 实体 + 迁移)
├── config/                   配置模型 + 默认配置(DEFAULT_CONFIG)
├── knowledge_base/           知识库(向量检索等)
├── computer/                 Agent 沙箱/电脑操作(高级)
├── tools/                    给 LLM 用的内置工具
├── skills/                   Skills 技能管理
├── backup/                   数据备份
├── utils/                    各种工具函数(路径/日志/指标…)
└── __init__.py               模块级"单例":logger、db_helper 等
```

**先不用记全。用的时候回来查就行。** 记住三个"★"枢纽即可:

1. `platform/` —— 消息从哪进来;
2. `pipeline/` + `event_bus.py` —— 消息进来后怎么被处理;
3. `provider/` —— 大脑(LLM)在哪。

## 快速对号入座:当你听到一个需求…

| 你想找 | 去哪个目录 |
|---|---|
| 消息怎么收发的 | `core/platform/sources/<平台名>/` |
| 想加一个大模型厂商 | `core/provider/sources/` |
| 插件是怎么被加载的 | `core/star/` |
| 一条消息的处理流程 | `core/pipeline/` + `core/event_bus.py` |
| 程序怎么启动的 | 根 `main.py` → `core/initial_loader.py` → `core/core_lifecycle.py` |
| 配置的默认值 | `core/config/default.py` |
| 网页控制台后端 | `astrbot/dashboard/server.py` |
| 网页控制台前端 | `dashboard/src/`(Vue) |
| 官方自带插件示例 | `astrbot/builtin_stars/` |

## 建议的"逛森林"顺序

1. 打开根 `main.py`,读到 `InitialLoader`(别深究)。
2. 打开 `core/core_lifecycle.py`,搜索 `async def initialize`,看它 `await` 了多少个 `xxx.initialize()`——这能直观感受"框架=一堆管理器"。
3. 打开 `core/platform/astr_message_event.py`,看类名和方法名(以后它无处不在)。
4. 最后再进 `core/pipeline/`,那是核心链路(笔记 09)。
