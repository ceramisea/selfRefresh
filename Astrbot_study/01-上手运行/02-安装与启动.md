# 02 · 安装与启动:把 AstrBot 跑起来

> 目标:在你自己电脑上成功启动 AstrBot,并在浏览器打开 WebUI 登录页。
> 官方参考:`docs/zh/deploy/astrbot/cli.md`(源码部署)、`README_zh.md` 的快速开始。

## 0. 你需要准备什么

| 需要 | 要求 | 说明 |
|---|---|---|
| 一台电脑 | Windows / macOS / Linux 均可 | 下面以 Windows 为主,Mac/Linux 命令差异会标注 |
| Python | **≥ 3.12** | 去 python.org 下载安装;Windows 安装时**务必勾选 "Add Python to PATH"** |
| 终端 | Windows 用 PowerShell 或 Cmd | 开始菜单搜 "PowerShell" |
| 网络 | 能访问 GitHub / PyPI | 首次安装依赖需要联网 |

> 建议:装完 Python 后,先开个终端敲 `python --version`,能看到 `Python 3.12.x` 之类的输出再继续。

## 1. 安装 uv(官方推荐的依赖管理工具)

uv 的作用是帮你创建独立的 Python 环境并安装依赖,**不会弄乱你系统里的其他 Python 环境**。

**Windows(PowerShell):**

```powershell
irm https://astral.sh/uv/install.ps1 | iex
```

**macOS / Linux:**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

装完**关掉终端重开一个**,输入 `uv --version`,有输出版本号即成功。

> 如果上面命令失败(比如网络问题),也可以先用 Python 装:`pip install uv`,效果一样。

## 2. 进入源码目录并安装依赖

打开终端,进入你解压出来的 AstrBot 源码文件夹。**注意:下面的命令都要在 AstrBot-master 文件夹里执行。**

用 `cd` 进入目录,例如源码在 `D:\CodeFiles2\github_project\AstrBot-master`:

```powershell
cd D:\CodeFiles2\github_project\AstrBot-master
```

> 小技巧:在文件管理器里打开 AstrBot-master 文件夹,在地址栏输入 `powershell` 回车,会直接在该目录打开终端。

然后安装依赖(uv 会自动读取 `pyproject.toml`):

```powershell
uv sync
```

第一次运行会下载很多依赖,可能需要几分钟,耐心等待,看到类似 `Installed N packages` / `Audited` 的字样就成功了。

> 如果中途网络很慢/失败,可以配置国内镜像后重试,见[附录 FAQ](../05-附录/13-常见问题与排错.md)。

## 3. 启动 AstrBot

继续在**同一个目录**执行:

```powershell
uv run main.py
```

看到一长串日志后,寻找关键信息:

- 一个像 `http://localhost:6185` 的链接 —— **这就是 WebUI 地址**;
- 首次启动若未设置密码,日志里会打印一个**随机初始密码**,同时用户名默认为 `astrbot`。

把 `http://localhost:6185` 复制到浏览器打开,能看到登录页就算**启动成功**了!

> 笔记里截图不易维护,真实日志里一般长这样(示意):
> `🌈 管理面板已启动,可访问: http://localhost:6185`
> 第一次启动还会自动生成 `data/` 数据目录和 `data/cmd_config.json` 配置文件。

**停止 AstrBot:** 回到终端按 `Ctrl + C`。

### 成功标志 ✅

- [ ] 浏览器能打开 `http://localhost:6185`
- [ ] 用 `astrbot` + 日志里的初始密码能登录(登录后记得改密码)

> 若登录后想马上动手配置,先去看 [03-认识WebUI控制台](03-认识WebUI控制台.md);若中途报错,先翻 [13-常见问题与排错](../05-附录/13-常见问题与排错.md)。

## 4. 那 README 里说的 `astrbot init / astrbot run` 是什么?

官方还提供了另一种**更省事**的方式——直接安装"已经打包好"的发布版(不是跑这份源码,而是从 PyPI 安装一份干净的 AstrBot):

```powershell
uv tool install astrbot --python 3.12
astrbot init      # 首次执行,初始化数据目录
astrbot run       # 启动
```

**两种方式怎么选?**

| | 方式 A:跑这份源码(推荐本笔记) | 方式 B:安装发布版 |
|---|---|---|
| 目的 | 学习/修改源码 | 快速体验、日常使用 |
| 跑的是 | 你下载的 AstrBot-master 代码 | PyPI 上的官方发布包 |
| 优点 | 能看代码、改代码、打断点 | 命令简单、自带打包好的网页 |
| 更新 | 重新下载源码 / `git pull` | `uv tool upgrade astrbot` |

> 本笔记按**方式 A** 讲解,因为它和你"读懂项目"的目标一致。当你只是想让机器人长期稳定跑着,方式 B 更方便。

## 5. 另一种常用部署:Docker(选学)

如果你熟悉 Docker,可以用容器跑,免去本机 Python 环境问题。仓库根目录已带 `Dockerfile` 和 `compose.yml`:

```powershell
docker compose up -d
```

详细说明见官方文档 `docs/zh/deploy/astrbot/docker.md`。**不熟悉 Docker 的新手可以先跳过这种方式。**

## 📌 小练习

1. 成功启动一次 AstrBot,并在浏览器里看到登录页。
2. 在终端里找到 WebUI 地址和初始密码打印在日志的哪几行。
3. `cd` 到别的目录再执行 `uv run main.py`,观察报错(会提示找不到依赖/不是有效目录)——这能帮你理解"命令必须在源码目录里执行"。
