# 05 · 接入聊天平台:让机器人住进 QQ / Telegram

> 目标:把 AstrBot 连到一个真实聊天平台,让朋友也能和它聊天。
> 官方参考:`docs/zh/platform/start.md`,以及各平台文档(见下表)。
> 对应源码:`astrbot/core/platform/`(平台适配器)。

## 先理解:什么是"平台适配器"

"接入平台"的本质是:**让 AstrBot 和某个聊天软件"接通消息"**。

- 每个聊天软件都有自己的接入方式(协议/SDK),AstrBot 把这些封装成一个一个**适配器(Platform Adapter)**;
- 你在 WebUI「机器人」页点几下,填入凭据,AstrBot 就会启动对应的适配器;
- 之后该软件里的消息会送进来,回复也会由适配器发回去。

对应到代码:适配器都放在 `astrbot/core/platform/sources/` 下,每个平台一个文件夹;启动时由 `PlatformManager`(`astrbot/core/platform/manager.py`)读取配置并运行它们。

## 去哪操作

WebUI 左侧「**机器人**」页 → 右上角「**创建机器人**」→ 选择平台 → 按提示填信息 → 保存。

## 新手推荐哪条路?

| 路线 | 平台 | 上手难度 | 说明 |
|---|---|---|---|
| **A(最快体验)** | 内置「聊天」ChatUI | ⭐ | 不用任何外部平台,WebUI 里直接对话(第 04 篇已用) |
| **B(推荐)** | **QQ 官方机器人** | ⭐⭐ | 有"一键扫码",凭据填得少,官方维护 |
| **C** | OneBot v11(如 NapCat) | ⭐⭐⭐ | 适合已有 NapCat/OneBot 环境的用户 |
| **D** | Telegram | ⭐⭐ | 需要能访问 Telegram 的网络;填一个 Bot Token 即可 |

> 如果想最快看到"在真实 IM 里跑",推荐路线 B(QQ 官方 WebSocket 接入,支持一键扫码)。

## 路线 B:QQ 官方机器人(推荐)

QQ 官方机器人目前推荐走 **WebSocket** 方式(不需要公网 IP,相对省事)。

1. 先去 QQ 开放平台申请一个机器人,拿到 **AppID** 和 **AppSecret**;或在 AstrBot 的创建界面用 **"一键扫码"** 辅助完成(界面会引导)。
2. WebUI「机器人」→ 创建机器人 → 类型选 **QQ 官方机器人(QQ Official / `qq_official`)**。
3. 填入 `AppID`、`AppSecret`。
4. 保存并等待状态变为"运行中"。
5. 把机器人拉进一个群,或私聊它发消息测试。

> 详细步骤(含沙箱、权限点、私聊/群聊开通)请看:
> `docs/zh/platform/qqofficial.md` 与 `docs/zh/platform/qqofficial/websockets.md`。

常见坑:

- QQ 机器人有**沙箱模式**,正式上线前只有白名单里的人能测;需要在 QQ 开放平台配置。
- 私聊消息要开"单聊"权限,群消息要开对应群权限。
- 机器人回复不了媒体消息时,通常是没装 `ffmpeg`(见下方通用坑)。

## 路线 C:OneBot v11(适合已有 NapCat 等协议端)

AstrBot 内置 OneBot v11(反向 WebSocket)适配器 `aiocqhttp`,此时 AstrBot 作为"服务端":

- 默认监听端口 **6199**,路径 `/ws`;
- 你需要在 **NapCat / OneBot 协议端**里配置"反向 WebSocket 连接"指向:
  `ws://你的AstrBot地址:6199/ws`
  (同一台机器测试就是 `ws://127.0.0.1:6199/ws`)
- 若设置 `ws_reverse_token`,两端要一致。

> 详细见 `docs/zh/platform/aiocqhttp.md`。

## 路线 D:Telegram

1. 找 `@BotFather` 创建一个机器人,拿到 **Bot Token**(形如 `123456:ABC-xxx`)。
2. WebUI「机器人」→ 创建 → 选 **Telegram**,填入 `telegram_token`。
3. 保存后在 Telegram 里给机器人发消息测试。

> 大陆网络需要给 AstrBot 配代理,或在服务商处选用海外服务器,详见 `docs/zh/platform/telegram.md`。

## 各平台最少要填的凭据速查

| 平台 | WebUI 里类型 | 关键凭据 |
|---|---|---|
| QQ 官方(WebSocket) | `qq_official` | AppID、AppSecret(可一键扫码) |
| QQ 官方(Webhook) | `qq_official_webhook` | AppID、AppSecret,需公网可回调 |
| OneBot v11 | `aiocqhttp` | 反向 WS 端口(默认 6199)、Token |
| Telegram | `telegram` | Bot Token |
| 微信公众号 | `weixin_official_account` | AppID、AppSecret、Token、EncodingAESKey |
| 企业微信 | `wecom` | CorpID、Secret 等 |
| 飞书 | `lark` | App ID、App Secret |
| 钉钉 | `dingtalk` | Client ID、Client Secret |
| Discord | `discord` | Bot Token |
| Slack | `slack` | Bot Token(及 App Token/签名密钥) |

> 每个平台的官方接入文档都在仓库 `docs/zh/platform/` 下,按平台名找即可。

## 让机器人能被"叫醒":唤醒/前缀配置

机器人不是每条消息都会理会,尤其在群里。默认通常通过**指令前缀**或 **@ 机器人**来触发:

- 内置指令前缀默认是 **`/`**(例如发 `/help` 看指令列表);
- 想直接和它对话(不敲 `/`),一般需要 **@它**,或在配置里调整"唤醒前缀/无前缀回复"等设置。

具体行为在「**配置文件**」页的"唤醒前缀 / 消息响应"相关项里调整;指令说明见 `docs/zh/use/command.md`。

## 通用坑:ffmpeg

> 官方建议:部署前装好 `ffmpeg` 并确保支持 `amr` 编码,否则**语音/视频等媒体消息**可能收发失败,微信类平台尤其需要。

## 验证:机器人活了没?

在平台里给机器人发一条消息:

- 发 `/help` → 应返回指令帮助(说明消息收发链路通);
- 直接和它聊天 → 应调用大模型回复(说明 Platform → Pipeline → Provider 全链路通)。

## 背后的代码(先混脸熟)

- 你创建的"机器人"对应 `data/cmd_config.json` 里 `platform` 配置段。
- `PlatformManager`(`astrbot/core/platform/manager.py`)启动后,每个平台适配器里都有一个 `run()` 方法在"监听消息"。
- 收到消息后,适配器会做两件事(笔记 09 细讲):把平台消息转成统一的 **`AstrMessageEvent`**,然后"提交事件"交给框架处理。

现在不用深究,只要记住:**平台侧的事,全在 `astrbot/core/platform/`;你在网页上创建机器人,就是让某个适配器跑起来。** 

## 📌 小练习

1. 至少成功接入一个真实平台并完成一次对话。
2. 查看 `data/cmd_config.json` 里 `platform` 配置段,看看你填的凭据以什么结构存放。
3. 思考:如果我想同时接入 QQ 和 Telegram,需要"创建几个机器人"?
