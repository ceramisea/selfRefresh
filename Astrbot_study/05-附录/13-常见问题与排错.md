# 13 · 常见问题与排错(FAQ)

> 收录新手最高频的问题。更多见仓库自带:`docs/zh/faq.md`、`docs/zh/others/diagnostics.md`。
> 通用排查口诀:**先看终端日志,日志里通常有答案。**

## 安装/启动相关

### Q1:提示 `Python 版本太低` / 找不到 Python
- 检查版本:`python --version`(Windows 也可能是 `py --version`)。
- 本项目要求 **Python ≥ 3.12**,去 python.org 下载安装。
- Windows 安装时勾选 **"Add Python to PATH"**,装完重开终端。

### Q2:提示 `uv 不是内部或外部命令`
- 说明 uv 没装好或 PATH 没生效。**重开一个终端**再试 `uv --version`。
- 仍不行:用 `pip install uv` 安装;然后 `python -m uv --version` 验证。
- 参考官方安装文档:<https://docs.astral.sh/uv/getting-started/installation/>

### Q3:`ModuleNotFoundError` 或奇怪的导入错误
- 多半是依赖没装全。回到项目目录重跑:`uv sync`,然后重新 `uv run main.py`。
- 如果你装过插件后报错,试试 `uv run --no-sync main.py`(避免插件依赖被重复安装/清理)。

### Q4:`astrbot run` 报"不是有效的 AstrBot 根目录"
- 因为你不在有效目录里。CLI 启动需要一个 `.astrbot` 标记(由 `astrbot init` 生成)。
- 在 AstrBot-master 目录下先执行 `astrbot init`;或用源码方式 `uv run main.py`(不需要该标记)。

### Q5:端口 6185 被占用,想换端口
- 启动前设置环境变量 `DASHBOARD_PORT`:
  - PowerShell:`$env:DASHBOARD_PORT=6186` 然后 `uv run main.py`
  - macOS/Linux:`DASHBOARD_PORT=6186 uv run main.py`
- 或用安装版 CLI 时加参数:`astrbot run --port 6186`。

### Q6:WebUI 打不开 `http://localhost:6185`
1. 看终端日志有没有"管理面板已启动"这一行;
2. 确认启动**没有报错退出**(Ctrl+C 之前窗口还挂着);
3. 若在服务器上部署,把 `localhost` 换成服务器 IP,并确保防火墙放行 6185。

## 登录/密码相关

### Q7:不知道登录密码
- 首次启动,**初始随机密码打印在终端日志里**(搜索"password"或"初始密码")。
- 用户名默认 `astrbot`。
- 也可以在启动前预设:`$env:ASTRBOT_DASHBOARD_INITIAL_PASSWORD="你的密码"`(PowerShell)。

### Q8:忘了密码 / 想重置密码
- 用重置参数启动:源码方式 `uv run main.py --reset-password`,安装版 `astrbot run --reset-password`。
- 启动后日志会打印新的初始密码,登录后立即修改。

## 机器人不回复/回复异常

### Q9:机器人完全不理我
按顺序排查:
1. **是否唤醒**:群里通常要 **@机器人** 或用指令前缀(默认 `/`)。先发 `/help` 试试,有回复说明链路通。
2. **是否接了大模型**:模型要在「模型提供商」里启用,且在「配置文件」中把"对话模型"选成它(见笔记 04)。
3. **看日志**:终端/WebUI「数据与日志」里有没有报错(如 API Key 无效、余额不足、网络超时)。
4. 私聊测一下,排除群权限问题。

### Q10:接了大模型但回复报错
- `AuthenticationError / 401` → API Key 不对或没填对。
- `quota / insufficient` → 账户没余额/额度。
- `timeout / connection` → 网络问题;DeepSeek 等国内服务一般直连即可,OpenAI 等可能需要代理。
- 大模型平台要求 `base_url` 以 `/v1` 结尾时补上,例如 DeepSeek `https://api.deepseek.com/v1`。

### Q11:发普通消息不回,但 `/help` 有反应
- 这是正常的"唤醒"机制:普通消息默认不触发大模型。
- 想让它直接聊:在群里 @它,或到「配置文件」调整唤醒/无前缀回复设置(见 `docs/zh/use/command.md`)。

## 平台接入问题

### Q12:QQ 官方机器人收不到消息/只有自己能测
- 多半是**沙箱模式**:QQ 开放平台未上线/未加白名单。去 QQ 开放平台完成配置、把测试账号加白名单。
- 确认已开通对应权限点(单聊/群聊)。
- 详细见 `docs/zh/platform/qqofficial/websockets.md`。

### Q13:OneBot(NapCat)连不上
- AstrBot 侧:创建机器人类型 `aiocqhttp`,记住反向 WS 端口(默认 **6199**)、路径 `/ws`、token。
- NapCat 侧:配置"反向 WebSocket"连接 `ws://AstrBot地址:6199/ws`,token 与 AstrBot 一致。
- 本机测试地址是 `ws://127.0.0.1:6199/ws`;跨机器要填真实 IP,并放行防火墙。
- 详细见 `docs/zh/platform/aiocqhttp.md`。

### Q14:Telegram 机器人没反应
- Telegram 在大陆网络不可直连;给 AstrBot 所在机器配代理,或用海外服务器。
- 详细见 `docs/zh/platform/telegram.md`。

### Q15:图片/语音等媒体消息收发失败
- 官方建议安装 **ffmpeg**(并确保支持 `amr` 编码)。微信类平台尤其需要。
- 安装后重启 AstrBot。

## 插件相关

### Q16:插件改了代码但没生效
- 到 WebUI「插件」页点「重载插件」(或该插件的 `...` → 重载),无需重启。
- 若加载失败,插件页会提示,可点"尝试一键重载修复"。

### Q17:插件文件夹放哪?
- 放 `AstrBot-master/data/plugins/<插件名>/`,里面必须有 `metadata.yaml` 和 `main.py`(见笔记 10)。
- 插件写错了导致 AstrBot 起不来?先删掉/移走该插件文件夹,能正常启动后再逐步排查。

## 配置与数据

### Q18:手改 `cmd_config.json` 把配置改坏了
- 先备份坏文件(`data/cmd_config.json`),再删掉它并重启——AstrBot 会重新生成默认配置(但你的设置会丢)。
- **日常请用 WebUI 改配置**,不要手改;确需手改前先备份。

### Q19:升级/重装会丢数据吗?
- `data/` 目录(配置、插件、数据库)是你自己产生的数据。升级源码前先**备份整个 `data/`**。
- 若只是替换源码文件,`data/` 在源码目录内,注意别被覆盖。
